## 1. 整数、浮点数与 Decimal

| 类型        | 适合表达什么    | 需要注意                          |
| --------- | --------- | ----------------------------- |
| `int`     | 精确整数      | 不受固定 32/64 位范围限制，但受内存和计算资源限制  |
| `float`   | 通常的近似数值计算 | 常用实现采用二进制浮点，很多十进制小数无法精确表示     |
| `Decimal` | 按十进制规则计算  | 能精确表示 `0.1`，但运算仍受上下文精度和舍入规则影响 |

```python
import math
from decimal import Decimal, localcontext

assert 0.1 + 0.2 != 0.3
assert math.isclose(0.1 + 0.2, 0.3)
assert math.isclose(1e-12, 0.0, abs_tol=1e-9)

assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
assert Decimal(0.1) != Decimal("0.1")

with localcontext() as ctx:
    ctx.prec = 6
    assert Decimal(1) / Decimal(3) == Decimal("0.333333")
```

`Decimal(0.1)` 转换的是已经产生近似误差的浮点值，所以从十进制文本构造通常更符合原意。Decimal 也不能用有限位数精确表示 `1/3`，不能简单理解成“永远没有误差”。[官方 Decimal 文档](https://docs.python.org/3/library/decimal.html)

比较近似结果时，按业务尺度选择 `math.isclose()` 的相对和绝对容差；接近零时常需要 `abs_tol`。这不意味着浮点数永远不能用 `==`，而是要先明确比较的是精确值还是有误差的计算结果。[官方浮点数说明](https://docs.python.org/3/tutorial/floatingpoint.html)

## 2. list、tuple、dict、set 各自表达什么

| 类型 | 语义 | 顺序 | 可变性 | 典型用途 |
| --- | --- | --- | --- | --- |
| `list` | 有序序列，可重复 | 按位置 | 可变 | 一批需要按顺序处理的数据 |
| `tuple` | 固定的对象引用序列 | 按位置 | 外层不可变 | 坐标、返回值组合 |
| `dict` | 键到值的映射 | 保留键的插入顺序 | 可变 | 配置、索引、字段记录 |
| `set` | 不重复元素的集合 | 不保证迭代顺序 | 可变 | 去重、成员判断、集合运算 |

```python
users = ["Alice", "Bob", "Alice"]
point = (100, 200)
profile = {"name": "Alice", "age": 20}
permissions = {"read", "write"}

assert users[1] == "Bob"
assert point[0] == 100
assert profile["name"] == "Alice"
assert "read" in permissions
assert len(set(users)) == 2

# 保留首次出现顺序的去重：元素需要可哈希
assert list(dict.fromkeys(users)) == ["Alice", "Bob"]
```

`key in d` 查字典的键，不是值；查值写 `value in d.values()`，通常要扫描。`dict` 的插入顺序从 Python 3.7 起是语言保证；修改现有键的值不会把它移到末尾。`set` 不适合承担顺序语义。[官方容器类型说明](https://docs.python.org/3/library/stdtypes.html#mapping-types-dict)

## 3. 为什么 set 查值通常比 list 快

### 先分清“按位置取”和“按值找”

下表是常用 CPython 容器的复杂度理解，`n` 为元素数；假设一次哈希或相等比较的代价可视为常数。

| 操作 | 常见复杂度 | 原因 |
| --- | --- | --- |
| `items[i]` | O(1) | 已知位置，直接定位元素引用 |
| `x in items`，items 是 list/tuple | 平均、最坏 O(n)；最好 O(1) | 按顺序检查，遇到匹配就停止 |
| `items.append(x)` | 摊还 O(1) | 多次追加平均很便宜，偶尔需要扩容 |
| `x in members`，members 是 set | 平均 O(1)，最坏 O(n) | 用哈希定位并处理冲突 |
| `mapping[key]`、`key in mapping` | 平均 O(1)，最坏 O(n) | 按键的哈希查找 |

`items[500]` 已经给出了位置；`500 in items` 只给出了值。后者不知道值位于哪里，通常需要依次比较对象身份或相等性。

### 哈希帮助缩小查找范围

以常用 CPython 实现为例，set 和 dict 使用哈希表。查找大致经历：

```text
待查对象 → 计算哈希 → 定位候选槽位 → 判断是否匹配
                                      │
                                      └─ 冲突时按探测规则继续查找
```

可以用 `hash(key) % 表容量` 理解“选择候选位置”；这是教学简化，实际 CPython 使用位运算和具体探测策略。哈希相同不代表对象相等，仍需确认对象是否匹配。字典在找到键后返回对应的值。[官方字典实现解释](https://docs.python.org/3/faq/design.html#how-are-dictionaries-implemented-in-cpython)

假设两个不同键落到同一候选位置，查找必须继续探测。CPython 的 set 会维护空槽、按需要扩容，并组合使用探测策略。一次查询可能访问多个槽位，因此不能理解成“永远只检查一次”。[CPython set 源码](https://github.com/python/cpython/blob/main/Objects/setobject.c)

### 平均 O(1) 有前提，也有成本

在哈希分布良好的常见情况下，查询探测量通常不会随集合大小线性增长。严重碰撞时可能退化；自定义 `__hash__()`、`__eq__()` 或很长数据本身的处理成本也需要计算。

构建一个 set 通常需要 O(n) 时间和额外内存。对大量重复查询，可以先构建一次；只查一次、小数据集，或者必须保留顺序和重复项时，不一定值得转换。

```python
known_ids = [101, 102, 103, 104]
incoming_ids = [102, 999, 104]

allowed = set(known_ids)  # 在循环外构建一次
matched = [item for item in incoming_ids if item in allowed]
assert matched == [102, 104]
```

对 `n` 个已知值做 `m` 次查询，list 扫描通常是 O(mn)；先构建 set 再查询，常见总成本为 O(n + m)。这描述增长趋势，不承诺固定的加速倍数。

### 为什么元素必须可哈希

插入和查找需要一致的定位依据。如果决定哈希与相等性的状态被改变，对象可能还在旧槽位，却按新哈希去别处查找。`list`、`dict`、`set` 因此不能直接作为集合元素或字典键。

哈希值稳定及相等性规则见 [[01-语言语义与执行模型#3. 身份、相等、可变性与哈希]]。另外，字符串等对象的哈希可能随进程变化，不要把 `hash()` 结果当作永久标识或密码学摘要。

## 4. 切片与推导式

### 切片：左闭右开，列表切片是浅拷贝

```python
items = [0, 1, 2, 3, 4]
assert items[1:4] == [1, 2, 3]
assert items[::2] == [0, 2, 4]
assert items[::-1] == [4, 3, 2, 1, 0]

copied = items[:]
assert copied == items
assert copied is not items
```

形式为 `sequence[start:stop:step]`，不包含 `stop`。列表切片生成新列表，但不会递归复制其中的对象；复制 k 个元素需要 O(k) 的时间和额外空间。

### 推导式：遍历、筛选、转换

```python
numbers = [1, 2, 3, 4]

assert [x * x for x in numbers] == [1, 4, 9, 16]
assert [x * x for x in numbers if x % 2 == 0] == [4, 16]
assert {x % 2 for x in numbers} == {0, 1}
assert {x: x * x for x in numbers} == {1: 1, 2: 4, 3: 9, 4: 16}

values = (x * x for x in numbers)  # 生成器表达式，不是元组推导式
assert next(values) == 1
assert list(values) == [4, 9, 16]
assert list(values) == []         # 已经消耗完
```

列表、集合、字典推导式会构建结果容器；生成器表达式在迭代时逐项产生值。转换逻辑复杂或包含很多副作用时，普通循环更容易读。[官方推导式与生成器表达式说明](https://docs.python.org/3/reference/expressions.html#displays-for-lists-sets-and-dictionaries)

## 5. str、Unicode、UTF-8 与 bytes

| 概念 | 所在层次 |
| --- | --- |
| Unicode | 为字符定义码点等规则 |
| `str` | Python 的 Unicode 文本，可理解为码点序列 |
| UTF-8 | 将文本编码为字节的一种规则 |
| `bytes` | 不可变字节序列，单个元素是 0–255 的整数 |

```python
text = "你好"
data = text.encode("utf-8")

assert len(text) == 2
assert len(data) == 6
assert data == b"\xe4\xbd\xa0\xe5\xa5\xbd"
assert data[0] == 0xe4
assert data.decode("utf-8") == text
```

**encode：str → bytes；decode：bytes → str。** 写文件和走网络时需要明确编码；解码规则不匹配可能报错，也可能生成乱码。

`len(str)` 统计码点，不一定等于肉眼看到的字符数。例如 `"e\u0301"` 是字母和组合重音两个码点，显示时可能看起来只有一个字符。截取字节时，也不能假定每个 UTF-8 字符只占一个字节。[官方 Unicode HOWTO](https://docs.python.org/3/howto/unicode.html)

## 6. 正则表达式与两层转义

Python 先解析字符串字面量，正则引擎再解析得到的模式。原始字符串 `r"..."` 可以减少第一层反斜杠转义，但正则引擎仍会解释 `\d`、`\n` 等模式。

```python
import re

assert "\n" != r"\n"               # 换行 vs 反斜杠和字母 n
assert re.findall(r"\d+", "abc123 def456") == ["123", "456"]
assert re.findall(r"\d+", "编号１２３") == ["１２３"]
assert re.findall(r"[0-9]+", "编号１２３") == []
assert re.fullmatch(r"[0-9]+", "123") is not None
assert re.fullmatch(r"[0-9]+", "123x") is None
```

常见选择：`search` 在任意位置找匹配，`match` 从开头匹配，`fullmatch` 要求整个字符串匹配，`findall` 收集匹配结果。对 Unicode 字符串，`\d` 不只匹配 ASCII 的 `0–9`；需要限定时使用 `[0-9]` 或相应 ASCII 标志。[官方 re 文档](https://docs.python.org/3/library/re.html)

## 7. 日期、时区与序列化

### 先区分本地钟面时间和确定的时刻

naive datetime 缺少确定时区所需的信息；aware datetime 带有可用时区信息。记录跨地区事件时，通常保存带时区的时间，按需转成 UTC；展示时再转换。

```python
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

utc_time = datetime(2026, 9, 28, 18, 30, tzinfo=timezone.utc)
berlin_time = utc_time.astimezone(ZoneInfo("Europe/Berlin"))

assert berlin_time.isoformat() == "2026-09-28T20:30:00+02:00"
assert berlin_time == utc_time
assert datetime.fromisoformat(berlin_time.isoformat()) == utc_time
```

`+02:00` 只是该时刻的 UTC 偏移，不等于完整的 `Europe/Berlin` 时区规则；夏令时变化需要时区数据库。`astimezone()` 转换同一时刻的表示；`replace(tzinfo=...)` 只是替换标签，不会自动换算钟面时间。[官方 datetime 文档](https://docs.python.org/3/library/datetime.html#aware-and-naive-objects)

上例依赖系统时区数据库；缺少数据的平台可安装 Python 的 `tzdata` 包。

### JSON 保留数据格式，不自动保留所有 Python 类型

`json.dumps()` 返回 `str`，`json.loads()` 解析 JSON。JSON 没有原生的 Decimal、datetime、bytes、set 类型，需要先约定表示方式；元组序列化后也不会自动还原成元组。

```python
import json
from datetime import datetime
from decimal import Decimal

payload = {
    "name": "你好",
    "amount": str(Decimal("12.30")),
    "at": "2026-09-28T20:30:00+02:00",
    "tags": sorted({"python", "notes"}),
}
text = json.dumps(payload, ensure_ascii=False, allow_nan=False)
wire = text.encode("utf-8")
restored = json.loads(wire.decode("utf-8"))

assert restored == payload
assert Decimal(restored["amount"]) == Decimal("12.30")
assert datetime.fromisoformat(restored["at"]).utcoffset().total_seconds() == 7200
assert json.loads(json.dumps((1, 2))) == [1, 2]
```

“转回 Python 对象”不等于“恢复原来的每一种类型”：字符串需要显式还原成 Decimal 或 datetime。`ensure_ascii=False` 决定 JSON 文本里中文的表现方式，UTF-8 编码则发生在 `encode()` 那一层。`allow_nan=False` 可避免输出非标准 JSON 数值 NaN/Infinity。[官方 JSON 文档](https://docs.python.org/3/library/json.html)
